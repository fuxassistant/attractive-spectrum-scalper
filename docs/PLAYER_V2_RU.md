# Иерархический игрок и графический инспектор

Реализовано разделение `P(участвовать) → P(LONG/SHORT | участие) → P(план | направление)`. Исследовательский gym, цены исполнения, часы, комиссия, размер и планы взяты из v1 без изменений. Старые код и результаты сохранены. Новые модули находятся в `spectrum/player_v2`, данные опыта — `data/research/player_v2/run_001`, визуальный инспектор — `reports/player_v2/run_001/index.html`.

## Решение и обучение

Сеть содержит общий causal LSTM и три группы выходов: два logits WAIT/TRADE, два LONG/SHORT и две группы по три exit-plan logits. Детерминированная политика сначала проверяет `P(TRADE)>0.5`; только затем выбирает направление и план. При ровно0.5 выбирается WAIT. Количество планов больше не уменьшает шансы участия через сравнение отдельных joint categories.

Стохастическое действие имеет точную вероятность `P(TRADE) × P(direction) × P(plan|direction)`, либо `1-P(TRADE)` для WAIT. PPO использует log-probability этого произведения. Маски учитываются до получения исполнимого распределения; при полном запрете входов effective gate=0, исходное намерение сети сохраняется отдельно. Вероятности направлений/планов после маски также отличаются от исходных выходов сети. Например, когда остаётся только fast, его допустимая вероятность=1 не означает уверенность модели в этом плане.

Наблюдение, счёт и reward — прежние:71 рыночный вход,7 параметров счёта, изменение liquidation equity/5, gamma1, GAE.95. WAIT не штрафуется. 1oz, $0.30 за оборот, вход по BBO строго после100ms, London08 → NewYork17, майский перерыв21–22UTC. Сохраняется правило support gap>5s. Планы fast12/8ticks120s, medium24/12ticks300s, wide40/20ticks600s.

Изменение относительно v1: **весь censored training episode исключается из actor и critic update**, включая предшествующие advantages. Неизвестный путь не становится отрицательным таргетом. Это не решает проблему поддержки источника: исключение целых эпизодов зависит от посещённых моделью действий и может смещать выборку. В текущем опыте из720 собранных дневных эпизодов288 допущены к градиенту,17 эпох пропущены без обновления. Если нет допустимых действий/полных эпизодов, optimize безопасно сообщает `updated=false`.

Три заранее фиксированных seed61015/61016/61017, по60 эпох. May4–7 — gradients, May8 — selection. Для каждого seed выбирается максимальный complete greedy net пятницы, при равенстве ранняя эпоха. Все три модели зафиксированы до новых evaluation-прогонов; победитель между seed по второй неделе не выбирается. После фиксации выполнены greedy, untrained, WAIT и три stochastic replay с seeds101/202/303. Дни May11–15 уже исследованы в v1: результаты имеют статус **development comparison, не fresh OOS**. Изменились и архитектура, и censor admission; это не изолированная абляция архитектуры относительно v1.

## Графический UI

Открыть локальный `reports/player_v2/run_001/index.html`. Все ресурсы локальные; нет CDN, API, аккаунта и публикации. JS-чанки позволяют загружать отдельную траекторию, а не всю историю сразу. Доступны243 траектории: все validation epochs0–60 для трёх seed, выбранные модели на обеих неделях, необученные и stochastic101 на второй неделе.

1. Выберите seed, траекторию, дату; в режиме проверочной пятницы — эпоху.
2. Двигайте общий курсор, выберите окно30мин/1час/3часа/10часов/вся сессия или включите «Ход цены».
3. Смотрите свечи, исходное намерение, effective gate, направление/планы, equity до действия и масштабированные входы по одному proof clock.
4. «Будущее (аудит)» открывает последующие точки; по умолчанию они скрыты, включая влияние будущих цен на масштаб осей. Журнал сделок и итоги дня явно ретроспективны.
5. «Деталь участия» увеличивает шкалу малых изменений около0.5; нулевые маски в этом режиме не рисуются. Sidebar всегда показывает effective gate и причину блокировки. Числа имеют достаточную точность, чтобы49.99% не выглядели равными50%.
6. «Планы после маски» переключает график исходных выходов сети и ограниченного распределения. Справа показано raw→allowed для каждого плана и прямой запрет.
7. «Следующая сделка» и «Пик намерения» переводят к событию. Точки чувствительности отмечены ромбами и доступны списком.

На120 точках сохранены signed gradient×standardized input для log-odds участия по causal prefix. Выбраны eligible peak, strongest rise и воспроизводимые случайные точки; при наличии сделок также первый вход. Показаны10 наибольших по модулю признаков, вклад счёта и наиболее чувствительные минуты префикса. Это **локальная чувствительность сети**, не SHAP, не причинное объяснение рынка и не калибровка прибыльности. Частота попадания признака в top10 также не является несмещённой глобальной важностью. Known flags нельзя трактовать как непрерывные физические действия над рынком.

Независимый Sol6.1 отметил flow/depth/FFT и availability flags, с локальным временным вкладом преимущественно недавнего префикса. Знаки различаются между seed/точками. Эти факты показывают использование информации, но не её экономическую полезность.

## Воспроизводимость

```powershell
# Новый опыт в отдельный отсутствующий каталог; эти две недели уже development-exposed.
.venv\Scripts\python.exe -m spectrum.player_v2 --run run_002 --epochs 60 --seeds 61015 61016 61017

# Экспорт существующего опыта без обучения/изменения выбора.
.venv\Scripts\python.exe -m scripts.player_v2_inspector --run run_001
.venv\Scripts\python.exe -m scripts.player_v2_scenes
node scripts/test_player_v2_ui.cjs reports/player_v2/run_001

# Проверки Python.
.venv\Scripts\python.exe -m pytest -q
```

Экспорт исходных heads использует соответствующий checkpoint и account trace каждой траектории и сверяет исходное намерение с сохранённым. На исходном GPU проходит строгая проверка; на CPU для длинного LSTM возможны малые отличия накопления, и экспорт прерывается при выходе за допуск вместо незаметной подмены сигнала. Сохранённый intent остаётся исходным из прогона. `source_snapshot` и протокол привязывают модель к коду, входные manifests — к данным.

Теперь можно отличать реальный рост намерения от снятия запретов, изменение gate от изменения направления, положительный исход от полезного ранжирования состояний. Следующий экономический эксперимент потребует новых недель и явно заданной проверки качества прогнозируемых последствий действий; менять порог по текущей второй неделе нельзя называть независимой валидацией.
