# Тест готовности недельных наблюдений

Эксперимент проверяет воспроизводимую генерацию причинного X для GCZ6 за
24–28 августа 2026. Входы включают пятницу 21 августа и воскресенье 23 августа.
Торговая неделя начинается в воскресенье в 22:00 UTC и заканчивается в пятницу
в 21:00 UTC. Маршрут `(1, 41271, 22)` объявлен по пятничному выбору контракта.

Проверенный результат: `OBSERVATION_PROFILE_AUDITED_WITH_LIMITATIONS`.
`serial_v2`: 236.34 s; `parallel2`: 193.87 s; ускорение 1.22×. Все 43 Parquet
побайтно совпали. 333 теста прошли. На торговой неделе присутствуют 413 995 из
414 000 открытых секунд; отсутствуют пять UTC-полуночей. На пяти UTC-днях
421 196 строк, но все 409 масок одновременно true лишь на 22 853 (5.43%).
Поэтому этот набор не получает автоматического допуска к обучению игрока.

Подробный отчёт с четырьмя просмотренными графиками:
`data/derived/feature_week_v1/audit/REPORT_RU.html`.
Численные receipts: `audit.json`, `admission.json`, `visual_review.json` в том же
каталоге. Итоговые данные находятся в `serial_v2`; `parallel2` — их проверенная
копия, полученная независимым запуском с двумя workers.

Замороженная библиотека `spectrum` не меняется. Новые файлы лежат в этом
эксперименте; большие данные и графики — в игнорируемом
`data/derived/feature_week_v1`. Исходные captures и старые результаты не изменяются.

## Состав профиля

| Поток | Состав | Публикация |
|---|---|---|
| Исходные котировки | BBO, размеры, epoch, ordinal, validity; ссылки и SHA исходных файлов | завершённый MBO event |
| `input_seconds.parquet` | канонические секунды, точные T-моменты, отдельные clocks | конец секунды + доказанная публикация |
| `features.parquet` | 409 значений, 409 булевых масок; motion, flow, spectral, depth_balance, volatility_vwap_proxy/exact | 1 s |
| `fast.parquet` | цена, глубина, поток сделок, изменения по сторонам книги, диагностические механизмы | 1 s; 51 канал в observation loader |
| `core_m1.parquet` | 166 значений и 166 масок, origin metadata | завершённая M1 |
| `minutes.parquet` | all-event OHLC, T-VWAP, native BB, спектр 128 M1 | завершённая M1 |
| `stores/DATE` | fast, контекст двух London anchors, состояния зон и события | `available_ns <= decision_ns`; 36 каналов дневного контекста |

Это полный **объявленный профиль**, а не обещание вычислить все 38 API семейства
на каждой секунде. Signature/queue/side-oriented/event-context wrappers требуют
отдельного набора решений, адресов BBO или выбранной стороны. Последовательности
и memory API также являются альтернативными представлениями, а не новыми
независимыми фактами рынка. Будущие targets здесь отсутствуют.

## Границы и неизвестные значения

- Цена — последняя более ранняя завершённая котировка с валидностью и возрастом.
  Никакой интерполяции через перерывы или пропуски нет.
- Физический `t_ns` отличается от `available_ns`. Потребитель обязан читать
  только уже опубликованные строки. Порог свежего секундного origin — 1 s.
- Числовой ноль при `known=false` — техническое хранение неизвестного.
- UTC-файл, торговая сессия CME и London anchor — три разные границы.
- Короткие окна не перескакивают через gap/epoch. Перед произвольным разрезом
  нужен checkpoint или достаточный левый контекст. Максимальный halo шести
  секундных семейств — 3606 строк. Core native SMA60 на M9 требует до 9 часов
  непрерывной истории; M1 спектр — 128 минут. Дневная/недельная память имеет
  собственные зависимости.
- В fixture нет полной предыдущей ISO-недели: соответствующие core-значения
  и маски принудительно обнулены. Одна пятница не объявляется целой неделей.
- `core` BB = SMA20 ± 2 sample SD (`ddof=1`); `representation` BB = SMA20 ± 2
  population SD (`ddof=0`). Имена и версии нельзя смешивать при создании labels.
- Снятие без связанного исполнения не доказывает намерение участника; refill —
  прокси по наблюдаемым пополнениям. Полная очередь и постоянная глубина зоны
  не выдаются за готовые признаки.

## Повторение

Из корня репозитория, используя закреплённую среду:

```powershell
.tmp\baseline\venv\Scripts\python.exe experiments\feature_week_v1\extract_context.py --workers 2
.tmp\baseline\venv\Scripts\python.exe experiments\feature_week_v1\profile.py --name serial_v2 --workers 1
.tmp\baseline\venv\Scripts\python.exe experiments\feature_week_v1\profile.py --name parallel2 --workers 2
.tmp\baseline\venv\Scripts\python.exe experiments\feature_week_v1\audit.py
.tmp\baseline\venv\Scripts\python.exe experiments\feature_week_v1\admission.py
.tmp\baseline\venv\Scripts\python.exe experiments\feature_week_v1\report.py
.venv\Scripts\python.exe experiments\feature_week_v1\plot.py
```

Создание output directory повторно запрещено: для нового опыта задайте новое
имя и передайте его в аудит. Raw extraction запускается один раз, если новых
контекстных sidecars ещё нет. Пять будних sidecars берутся из предыдущей
материализации после проверки SHA и идентичности исходного раздела MBO.
Новая среда визуализации применяется только к графикам, не к расчёту признаков.

`profile.py` проверяет входные SHA, соответствие объёмов точных T-принтов
каноническим счётчикам, запись/чтение Parquet и реальный observation loader.
`audit.py` независимо считает VWAP/дисперсию по сырым T-принтам, обе формулы BB,
оконный DFT, ценовой путь и потоки; сравнивает batch/checkpoint, будущий prefix,
однопроцессную и двухпроцессную генерацию; измеряет покрытие и частоту изменения.
Это численная и описательная проверка; причинность всего стека не доказывается
одним prefix-тестом.

Первый smoke был отклонён из-за ошибки позиционного соединения индексов в новом
адаптере точных моментов; исправление покрыто тестом. Первый полный serial-run
остановился на конфликте имён origin metadata и core-признаков. Эти каталоги
сохранены с REJECTED/FAILED, они не являются итоговым датасетом.

## Критерий готовности

Различаются: корректный источник, корректное причинное представление,
содержательное X, пригодность для конкретного target, интеграция игрока и
прибыльность. Этот опыт проверяет первые три уровня и сохраняет ограничения.
Готовность к обучению игрока требует отдельного договора о decision clock,
геометрии пересечения, правилах WAIT/entry/exit, fill/costs, censoring и
хронологических train/validation/test-разделах.

Официальные определения:
[торговые часы и спецификация GC](https://www.cmegroup.com/markets/metals/precious/gold.timeAndSales.html),
[определение `ddof` в NumPy](https://numpy.org/doc/stable/reference/generated/numpy.std.html).
